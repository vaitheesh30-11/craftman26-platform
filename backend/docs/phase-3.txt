## 2. Directory Layout & Module Responsibilities

Codex must generate the Phase B3 WebSocket layer within this strict structure:

* **`backend/app/`**
  * **`schemas/`**
    * **`ws_dto.py`** — Pydantic V2 models defining the strict structure of outbound WebSocket JSON payloads.
  * **`websockets/`**
    * **`auth.py`** — JWT extraction and validation logic specifically tailored for WebSocket query parameters.
    * **`ws_manager.py`** — The singleton Connection Manager tracking active sockets per `session_id`.
    * **`stream_bridge.py`** — The async queue processor that bridges LangGraph's `.astream_events()` output to the `ws_manager`.
    * **`router.py`** — The FastAPI WebSocket endpoint definitions (`@router.websocket`).

## 3. WebSocket Connection Management & State Recovery

### 3.1 The Connection Pool (`ws_manager.py`)
* **Data Structure:** Maintains an in-memory dictionary mapping session IDs to active connections: `active_connections: dict[str, list[WebSocket]]`.
* **Thread Safety:** Must use `asyncio.Lock()` when appending or removing connections to prevent race conditions during high-concurrency disconnects.

### 3.2 Handshake & Auth Protocol (`auth.py`)
1. Client initiates connection: `wss://api.sentinel-iq.com/ws/drift/{session_id}?token=<JWT>`
2. The endpoint extracts the `token` parameter.
3. Invokes the `verify_jwt_token` utility. If the signature is invalid or expired, the backend instantly calls `websocket.close(code=status.WS_1008_POLICY_VIOLATION)`.

### 3.3 State Recovery Protocol (The "Catch-Up" Sync)
When a Next.js client successfully connects or reconnects:
1. The `ws_manager` accepts the connection.
2. It queries the `governance_sessions` table for the specified `session_id`.
3. It extracts the `state_tensor_snapshot` (specifically the `working_policy_json` and `debate_log`).
4. It immediately pushes a `STATE_SYNC` event down the socket to ensure the UI is perfectly synchronized with the backend before new events arrive.

## 4. Pydantic V2 Event Payloads (`ws_dto.py`)

All data pushed over the WebSocket must be serialized using strict Pydantic V2 DTOs. Raw dictionaries are forbidden.

### 4.1 Base Event Schema
* **`event_id`**: UUID.
* **`session_id`**: String.
* **`timestamp`**: DateTime (ISO 8601).
* **`event_type`**: String Enum (`STATE_SYNC`, `AGENT_TURN_EMITTED`, `POLICY_AST_UPDATED`, `PROOF_STATUS_UPDATED`, `INTERRUPT_REACHED`, `MUTATION_COMMITTED`).

### 4.2 `AgentTurnEmittedDTO`
Inherits Base.
* **`coalition`**: String (`SUPERVISOR`, `ALPHA_SYNTHESIS`, `BETA_SIMULATION`, `GAMMA_CONTEXT`).
* **`agent_id`**: String (e.g., `AST_Compiler_Agent`).
* **`action_taken`**: String.
* **`formal_feedback`**: Optional String.

### 4.3 `PolicyAstUpdatedDTO`
Inherits Base.
* **`working_policy_json`**: String.
* **`byte_size`**: Integer.

### 4.4 `ProofStatusUpdatedDTO`
Inherits Base.
* **`zelkova_status`**: String (`PASS`, `FAIL_PRIVILEGE_ESCALATION`).
* **`counter_examples`**: List of Strings.
* **`blast_radius_score`**: Float.

## 5. The LangGraph Event Bridge (`stream_bridge.py`)

The multi-agent engine must not be slowed down by WebSocket network I/O. The system utilizes an **Async Queue Decoupling Pattern**.

### 5.1 The Producer (LangGraph Callback)
* While `sentinel_engine.astream()` is running, it yields state updates.
* A lightweight callback function captures these updates, wraps them in the appropriate Pydantic V2 DTO, and pushes them into an `asyncio.Queue` (e.g., `event_queue.put_nowait(payload)`).

### 5.2 The Consumer (Stream Bridge Worker)
* A dedicated background task (`asyncio.create_task(process_event_queue())`) constantly awaits items from the `asyncio.Queue`.
* When an event arrives, it identifies the target `session_id`.
* It calls `ws_manager.broadcast_to_session(session_id, payload_json)`.
* **Dead-Socket Handling:** If a socket raises a `ConnectionClosed` exception during the broadcast, the manager automatically catches the exception, removes the dead socket from the pool, and continues broadcasting to the remaining clients.

## 6. Execution Directives for Codex

When assigning Phase B3 to Codex, instruct it to:

1. **Build the Payloads (`app/schemas/ws_dto.py`):**
   * Implement the base and specialized event DTOs using Pydantic V2 `BaseModel` and strict `Field` annotations.
2. **Build the Auth Gate (`app/websockets/auth.py`):**
   * Write a FastAPI dependency specifically for extracting and validating JWTs from WebSocket query strings.
3. **Build the Connection Manager (`app/websockets/ws_manager.py`):**
   * Implement a singleton class managing `dict[str, list[WebSocket]]`.
   * Implement the `STATE_SYNC` recovery protocol querying the database upon successful `connect()`.
4. **Build the Bridge & Queue (`app/websockets/stream_bridge.py`):**
   * Implement the decoupled `asyncio.Queue` pattern.
   * Write the background consumer loop that reads from the queue and executes `.send_text()` on active sockets.
5. **Build the Endpoint (`app/websockets/router.py`):**
   * Define the `@router.websocket("/{session_id}")` endpoint, tying together auth, connection registration, and disconnection handling.
