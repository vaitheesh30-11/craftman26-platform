## 2. Directory Layout & Module Responsibilities

Codex must generate the Phase B5 execution layer within this strict structure:

* **`backend/app/`**
  * **`services/`**
    * **`aws_mutator/`**
      * **`base_executor.py`** — Abstract execution class handling STS credential injection and AWS API rate-limit backoffs.
      * **`scp_executor.py`** — Boto3 adapter targeting AWS Organizations to update Service Control Policies.
      * **`iam_executor.py`** — Boto3 adapter targeting IAM Managed and Inline policies.
      * **`sso_executor.py`** — Boto3 adapter targeting AWS IAM Identity Center (SSO) to revoke stale permission sets.
    * **`ttl_scheduler.py`** — EventBridge Scheduler integration managing ephemeral break-glass permission teardowns.

## 3. The Mutation Execution Architecture

The execution layer is strictly "air-gapped" from the Agentic AI. It cannot be invoked by LangGraph directly. It only executes when the FastAPI `/approve` REST controller (Phase B2) passes a cryptographically verified `working_policy_json` payload.

### Execution Workflow
1. **Approval Signal:** The REST controller invokes the Mutator Service with the final verified JSON and the `target_arn`.
2. **Credential Fetch:** The Mutator requests a scoped STS session from the Boto3 Session Factory (Phase B1) targeting the specific AWS Account.
3. **Execution Routing:** Based on the `active_problem_id`, the base executor routes the payload to the corresponding adapter (`scp_executor`, `iam_executor`, etc.).
4. **AWS API Call:** The specific adapter applies the JSON document to AWS.
5. **Context Tagging:** The adapter issues a tag update to the modified resource appending `SentinelIQ:SessionID` and `SentinelIQ:LastModified`.
6. **TTL Scheduling (If Applicable):** For temporary access (Problem `SCP-5`), the scheduler registers an EventBridge target.

## 4. AWS Boto3 Integration Contracts

### 4.1 Organizations SCP Executor (`scp_executor.py`)
* **Target Problems:** `SCP-1`, `SCP-2`, `SCP-3`, `SCP-4`.
* **AWS Service:** `boto3.client('organizations')`.
* **Action Contract:** Invokes `update_policy`.
  * Passes the target `PolicyId` extracted from the state.
  * Passes the minified `working_policy_json` into the `Content` parameter.
* **Failsafe:** If the JSON exceeds the 10,240-byte quota, the Boto3 client throws a `LimitExceededException`. The executor catches this, flags the session as `FAILED`, and routes a rollback message.

### 4.2 IAM Policy Executor (`iam_executor.py`)
* **Target Problems:** `IAM-1`, `IAM-2`.
* **AWS Service:** `boto3.client('iam')`.
* **Action Contract (Managed Policies):** Invokes `create_policy_version` and flags `SetAsDefault=True`. Deletes the oldest non-default version if the maximum version limit (5) is reached.
* **Action Contract (Inline Policies):** Invokes `put_role_policy` for cross-account trust adjustments.

### 4.3 SSO Permission Revoker (`sso_executor.py`)
* **Target Problem:** `IAM-3` (SSO Creep).
* **AWS Service:** `boto3.client('sso-admin')`.
* **Action Contract:** Invokes `delete_account_assignment`. Safely removes the inactive SSO permission set binding without deleting the user identity.

## 5. Ephemeral Break-Glass Lifecycle (`ttl_scheduler.py`)

For emergency P1 outage requests (`SCP-5`), the system grants elevated permissions but guarantees their removal via AWS EventBridge Scheduler.

### EventBridge Configuration Strategy
* **AWS Service:** `boto3.client('scheduler')`.
* **Action Contract:** Invokes `create_schedule`.
* **Schedule Expression:** Uses the `at(yyyy-mm-ddThh:mm:ss)` format representing the exact current UTC time plus the requested TTL duration (e.g., $+7200$ seconds).
* **Target Configuration:**
  * Configured with a dedicated `RoleArn` for the EventBridge execution context.
  * The Target API is a webhook pointing back to the Sentinel-IQ ingestion pipeline, or an isolated AWS Lambda function designed to revert the specific `target_arn` to its `baseline_policy_json` state.
* **Resiliency:** Configures the scheduler with a Dead-Letter Queue (DLQ) and sets `MaximumRetryAttempts` to 10 to guarantee execution even during regional API stutters.

## 6. Execution Directives for Codex

When assigning Phase B5 to Codex, instruct it to:

1. **Build the Base Executor (`app/services/aws_mutator/base_executor.py`):**
   * Write an abstract factory pattern that accepts the target ARN and problem ID, automatically retrieving the correct cross-account Boto3 STS credentials.
2. **Build the AWS Adapters (`scp_executor.py`, `iam_executor.py`, `sso_executor.py`):**
   * Implement the exact Boto3 function calls (`update_policy`, `create_policy_version`, `delete_account_assignment`).
   * Include strict AWS exception handling (e.g., catching `MalformedPolicyDocumentException` and `LimitExceededException`).
3. **Build the EventBridge Scheduler (`app/services/ttl_scheduler.py`):**
   * Implement the logic to calculate the ISO-8601 TTL timestamp.
   * Write the Boto3 implementation for `create_schedule` utilizing the `at()` schedule expression and passing the rollback state payload to the target configuration.
4. **Integrate with the HITL Controller:**
   * Wire the execution sequence so that the mutator is called as the final blocking step in the Phase B2 `hitl_approvals.py` REST endpoint.
