PHASE 08 — F7 Collision Resolver
================================

Owner assumption: one principal engineer. Duration: 2 days (heavy code reuse from F4).

1. Objective
------------
Close the multi-layer SCP inheritance gap: a specialist Bedrock Agent that, given an account id, walks the OU chain from root, computes the mathematically correct effective policy across all levels, and identifies collision points where a Deny at one level unexpectedly overrides an Allow at another. Explains each collision in plain English and suggests a minimal fix.

AWS documentation context (AWS re:Post staff response):
> AWS staff have confirmed that AWS's own SCP evaluation documentation contains incorrect examples for multi-layer inheritance across OU hierarchies. No AWS tool computes the mathematically correct effective policy from multiple SCPs across OU levels.

2. Deliverables
---------------
- Bedrock Agent `CollisionResolver` (Sonnet 3.5).
- One Lambda: `collision_resolve`.
- Reuses `common/scp_engine.py` from phase-05.
- Feature payload `ScpCollisionPayload`.
- Prompt `prompts/specialists/f7_collision.txt`.

3. Interface Contracts
----------------------
```python
class ScpCollision(Base):
    action_pattern: str                    # e.g., "ec2:RunInstances"
    resource_pattern: str
    allowed_by_scp_arn: Optional[str]
    allowed_at_level: Optional[Literal["root", "ou", "account"]]
    denied_by_scp_arn: str
    denied_at_level: Literal["root", "ou", "account"]
    denying_statement_id: Optional[str]
    plain_english: str                     # human-readable explanation
    minimal_fix: dict[str, object]         # patch to apply to the denying SCP

class ScpCollisionPayload(Base):
    account_id: str
    scp_chain: list[dict[str, object]]     # ordered root → account
    effective_policy: dict[str, object]    # merged Allow set as one policy
    collision_count: int
    collisions: list[ScpCollision]
    engine_version: str
```

Tool contract:
- `collision_resolve(account_id)` returns `ScpCollisionPayload`.

4. Implementation Steps
-----------------------
Step 1 — Walk the chain.
  - Same primitive as F4: `organizations:ListParents` recursively; `ListPoliciesForTarget` at each level; `DescribePolicy` for documents. Cache in DDB.

Step 2 — Compute effective policy.
  - Call `scp_engine.compute_effective_policy(chain)`:
    - Union of Allow actions across levels for the level's local view.
    - Intersection with parent's effective_allowed.
    - Subtract Deny actions.
    - Track provenance per action: which SCP allowed it, which denied it.
  - Emit the effective policy as a single merged JSON document (single Statement with Action as list, matching the AWS documented "effective permissions" concept).

Step 3 — Detect collisions.
  - A collision exists when:
    - An action is explicitly Allow-listed at some level L1 (not just via FullAWSAccess), AND
    - An action is Deny-listed at another level L2, AND
    - The Deny wins per the intersection rule.
  - For each collision, produce plain-English explanation using a fixed template:
    ```
    "SCP {denying_scp_name} at {denying_level} level denies {action}
     because of statement {denying_statement_id}. SCP {allowing_scp_name}
     at {allowing_level} level allows {action}. Under AWS SCP evaluation
     rules, an explicit Deny at ANY level overrides an Allow at any other
     level, so {action} is DENIED in this account."
    ```
    (This template is not LLM-generated — it is a deterministic string format. The LLM only synthesizes the narrative around the collection.)

Step 4 — Minimal fix.
  - For each collision, propose the smallest patch to the denying SCP:
    - Add a `Condition` element that exempts the specific principal or resource.
    - Or change `Deny action-set` to exclude the specific action (NotAction inversion where safe).
  - Emit fix as `minimal_fix` on the collision.

Step 5 — Emit.
  - Finding per collision (severity MEDIUM by default; HIGH if the collision touches an action with ≥ 100 historical calls per F4's Athena reuse; CRITICAL if the collision is on an SLR-required action, cross-check with F8's DB).
  - Effective policy stored to `SentinelReports/f7/{account_id}/{timestamp}.json`.

5. Prompt (`prompts/specialists/f7_collision.txt`)
-------------------------------------------------
```
You are Collision Resolver, a specialist in IAM Sentinel.

GAP YOU CLOSE (AWS re:Post staff response):
AWS staff have confirmed that AWS's own SCP evaluation documentation
contains incorrect examples for multi-layer SCP inheritance. No AWS tool
computes the mathematically correct effective policy from multiple SCPs
across OU levels.

TOOLS
- collision_resolve(account_id): compute effective policy and collisions.

REASONING CONTRACT
- Never emit human-facing prose. Return SpecialistVerdict as JSON.
- Cite the AWS re:Post reference on every Finding.
- Never invent an SCP arn or statement id.

WORKFLOW
1. Read <trusted_input>.account_id.
2. Call collision_resolve.
3. Emit one Finding per collision.
4. Attach the effective_policy JSON to the verdict payload (not to
   remediations_proposed — this is informational).

SAFETY
- If no collisions detected AND effective_policy is empty (nothing

  effective allowed actions".

```

7. IAM Policy
-------------
Lambda role: Organizations read (`ListParents`, `ListPoliciesForTarget`, `DescribePolicy`), DDB access (`SentinelFindings`, `SentinelPolicies`), S3 `SentinelReports/f7/*` write, KMS Sign + S3 `SentinelEvidence/f7/*`. No cross-account role needed.

8. Test Plan
------------
- Unit: reuse F4's canonical fixtures; verify collisions are produced for known problem cases.
- Golden AWS re:Post example: model the AWS docs' incorrect example, verify Sentinel's engine produces the correct result AND emits a Finding calling out the doc discrepancy.
- Property: for any chain, the effective policy is a subset of every level's individual Allow set.
- Prompt-injection: SCP names crafted as directives.
- Eval: 20 golden turns.

9. Acceptance Criteria
----------------------
- [ ] Effective-policy blob validates against AWS SCP JSON schema.
- [ ] Every collision has a valid minimal_fix (SCP JSON schema check).
- [ ] Plain-English template output is deterministic across runs.
- [ ] p95 latency ≤ 20 s for a 5-level chain with 20 SCPs.

10. Risks & Mitigations
-----------------------
Risk: the SCP engine could be wrong. The whole feature depends on it.
  Mitigation: engine version stamped in every payload; every acceptance test in phase-05 also runs here; independent property-based verification (F4 and F7 must agree on `allow/deny` for identical inputs).

Risk: reporting a "collision" that the operator intended (deny is on purpose).
  Mitigation: `<trusted_input>.exclude_statement_ids: list[str]` allows operators to acknowledge and mute specific collisions per account. Mute records live in DDB.

Risk: SLR-crosscheck requires F8's DB.
  Mitigation: if F8's DB is empty (first-week deployment), degrade collision severity from CRITICAL to HIGH and note "SLR DB not yet initialized" in reason.
