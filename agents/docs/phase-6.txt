## 4. Infrastructure Stack Specifications

### 4.1 Networking & Security Stack (`networking_stack.py` & `security_stack.py`)
* **VPC Footprint:** 3 Availability Zones, 3 Public Subnets, 3 Private Application Subnets, and 3 Isolated Database Subnets.
* **VPC Endpoints (AWS PrivateLink):** Private interfaces for Amazon Bedrock (`bedrock-runtime`), AWS Access Analyzer (`accessanalyzer`), AWS STS (`sts`), Organizations (`organizations`), and DynamoDB (`dynamodb`). Prevents agent traffic from traversing the public internet.
* **Encryption Standards:** AWS KMS Customer Managed Keys (CMK) with automatic annual rotation for encrypting Neptune clusters, OpenSearch indexes, SQS queues, and S3 WORM buckets.

### 4.2 Database & Dual-Memory Stack (`database_stack.py`)
* **Amazon Neptune Cluster Spec:**
  * Engine: Neptune Serverless (`db.serverless`).
  * Scaling Bounds: 2.5 NCU (Neptune Capacity Units) to 128 NCU.
  * Multi-AZ high availability with an automated read replica in AZ-2.
  * Audit Logging enabled for openCypher graph traversals.
* **Amazon OpenSearch Serverless Spec:**
  * Collection Type: `SEARCH` (Vector Search).
  * Compute Units: Minimum 2 OCU (OpenSearch Capacity Units) for Indexing, 2 OCU for Search.
  * Encrypted at rest via KMS CMK; Network Policy enforces private VPC access only.

### 4.3 Queue & Event Pipeline Stack (`queue_stack.py`)
* **EventBridge Rule:** Matches AWS Organizations (`UpdatePolicy`, `CreatePolicy`), IAM (`PutRolePolicy`), and STS AccessDenied events.
* **SQS FIFO Queue:** `sentinel-drift-events.fifo` configured with `ContentBasedDeduplication=true` and a 14-day message retention period.
* **Dead-Letter Queue (DLQ):** Messages failing processing 3 times are routed to `sentinel-drift-dlq.fifo` for SRE inspection, triggering a CloudWatch Alarm.

### 4.4 Compute Engine Stack (`compute_stack.py`)
* **Execution Platform:** AWS ECS Fargate running ARM64 (AWS Graviton3) containers to optimize cost-performance for heavy async processing.
* **Task Allocation:** 2 vCPU, 4 GB RAM per task instance.
* **Auto-Scaling Policy:** Scales out when SQS Queue backlog exceeds 50 messages or ECS CPU utilization exceeds 70% for 2 consecutive minutes.
* **State Checkpointing:** LangGraph session states checkpointed to Amazon DynamoDB (`sentinel_langgraph_checkpoints`) with Strong Consistency enabled.

### 5.1 CI Stage Contract (`.github/workflows/agent_ci_eval.yml`)
* **Trigger:** Pull Requests targeting `main` or `release/*`.
* **Execution:** Spawns an ephemeral test environment containing local Neptune and OpenSearch mocks.
* **Gate Assertions:**
  1. `eval_pass_rate >= 0.95` (Overall benchmark suite pass percentage).
  2. `zelkova_smt_proof_rate == 1.00` (Zero privilege escalations allowed).
  3. `byte_limit_compliance == 1.00` (Zero generated SCPs exceeding 10,240 bytes).

### 5.2 CD Stage Contract (`.github/workflows/agent_cd_deploy.yml`)
* **Trigger:** Merge to `main` branch post-CI approval.
* **Strategy:** Blue/Green ECS Deployment using AWS CodeDeploy.
* **Canary Schedule:** Shifts 10% traffic to the new revision, waits for a 15-minute soak period monitoring CloudWatch error rates, then shifts remaining 90% traffic.
* **Auto-Rollback Trigger:** Automatically rolls back if ECS task health checks fail or HTTP 5xx responses exceed 1% during the canary window.

## 6. Execution Directives for Codex

When generating Phase 6 Infrastructure-as-Code and deployment modules:

1. **CDK Constructs (`infra/cdk/stacks/`):**
   * Define multi-AZ VPC topologies with PrivateLink VPC Endpoints.
   * Configure Neptune Serverless clusters, OpenSearch Serverless collections, SQS FIFO queues, and ECS Fargate Task Definitions.
2. **Terraform Modules (`infra/terraform/modules/`):**
   * Declare modular infrastructure resources matching the CDK specification for environment portability.
3. **CI/CD Workflows (`.github/workflows/`):**
   * Build `agent_ci_eval.yml` to execute Phase 4 evaluations and enforce strict quality gates.
   * Build `agent_cd_deploy.yml` for zero-downtime, Blue/Green ECS canary deployments.
