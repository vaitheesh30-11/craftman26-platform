## 3. The API Bridge: React Query Hooks (`hooks/api/useSessionApi.ts`)

This is the critical glue layer connecting the Next.js Frontend to the FastAPI Backend. Codex must implement these using `axios` and `@tanstack/react-query`.

### 3.1 `useGetSessionDetail(sessionId)`
* **Type:** Query (`useQuery`).
* **Endpoint:** `GET /api/v1/sessions/{sessionId}`
* **Behavior:** Fetches the `SessionDetailResponseDTO`. Populates the baseline JSON, current working JSON, and blast radius into the UI.

### 3.2 `useApproveSessionMutation()`
* **Type:** Mutation (`useMutation`).
* **Endpoint:** `POST /api/v1/sessions/{sessionId}/approve`
* **Payload:** `ApprovalSubmitDTO` (`approverArn`, `approvalNotes`, `overridePolicyJson`).
* **Behavior:** 
  * On success: Triggers `queryClient.invalidateQueries` to refresh the dashboard, and displays a success Toast notification ("Mutation Committed to AWS").
  * On error: Displays a destructive Toast notification with the FastAPI error message.

---

## 4. Interactive Monaco AST Diff Editor (`ASTDiffEditor.tsx`)

This component provides a side-by-side code comparison, exactly like GitHub's PR review UI, but specialized for AWS IAM/SCPs.

### 4.1 Technology & Configuration
* **Library:** `@monaco-editor/react` using the `<DiffEditor />` component.
* **Theme:** `vs-dark` (customized to match the Zinc/Obsidian SOC aesthetic).
* **Language:** `json`.
* **Validation:** Monaco's native JSON worker must be enabled to highlight missing quotes, trailing commas, or bracket mismatches.

### 4.2 Editor State Management
* **Left Panel (Original):** Binds to `baseline_policy_json`. Strictly read-only.
* **Right Panel (Modified):** Binds to `working_policy_json`. 
* **Edit Mode:** By default, the right panel is read-only. The user must click a "Enable Manual Override" toggle to unlock the right panel for editing.
* **Callback Hook:** Emits `onTargetPolicyChange(newJson)` up to the parent component whenever the human types.

### 4.3 Byte Quota Gauge (`ByteQuotaGauge.tsx`)
* Placed directly below the Monaco Editor.
* Calculates the byte length of the minified JSON string from the right panel.
* **Visual States:**
  * Green: $0$ – $8,000$ bytes.
  * Yellow Warning: $8,001$ – $10,239$ bytes.
  * Red Error: $\ge 10,240$ bytes. Disables the "Approve" button immediately.

## 5. HITL Control Panel (`HITLControlPanel.tsx`)

This is the primary action workspace for the Security Administrator.

### 5.1 Dynamic Button States
The primary action button must intelligently adapt based on user behavior:
1. **State 1 (Clean Approval):** If the user has *not* edited the Monaco JSON, and the Zelkova status is `PASS`.
   * Button: `[ Approve & Deploy to AWS ]` (Green).
   * Action: Opens the `ManualOverrideModal` to collect mandatory audit notes, then fires `useApproveSessionMutation`.
2. **State 2 (Human Override Detected):** If the user types in the Monaco editor.
   * Button: `[ Re-Run Zelkova SMT Proof ]` (Purple/Indigo).
   * Action: Warns the user that human edits must be mathematically proven before deployment.
3. **State 3 (Unsafe State):** If Zelkova status is `FAIL_PRIVILEGE_ESCALATION` or JSON syntax is invalid.
   * Button: `[ Deployment Blocked ]` (Disabled, Red border).

### 5.2 Mandatory Audit Log Modal (`ManualOverrideModal.tsx`)
* Before the API mutation fires, a Radix UI Dialog must appear.
* Requires the user to select their AWS Identity/Role.
* Requires a text input: "Justification for Security Audit (minimum 10 characters)."
* Connects the submit button directly to the React Query API mutation.
