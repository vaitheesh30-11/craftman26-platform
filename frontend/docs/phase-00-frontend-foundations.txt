PHASE 00 — Frontend Foundations
================================

Owner assumption: one principal engineer. Duration: 2 days.

1. Objective
------------
Stand up the Next.js 14 App Router project with Amplify auth, Tailwind + shadcn/ui, TanStack Query, MSW, and a typed backend client generated from OpenAPI.

2. Deliverables
---------------
- `package.json` with pinned deps.
- `app/layout.tsx` with `AuthGate` and top-level providers (Query, Toast).
- `lib/api-client.ts` — typed client generated by `openapi-typescript` at build.
- `lib/auth.ts` — Amplify wrappers.
- `app/api/proxy/[...path]/route.ts` — BFF proxy.
- MSW handlers under `mocks/`.
- Tailwind + shadcn/ui base setup.
- Vitest + Playwright configured.

3. Auth Flow
------------
- Amplify configured with Cognito hosted UI (from `NEXT_PUBLIC_COGNITO_POOL_ID`, `NEXT_PUBLIC_COGNITO_CLIENT_ID`, `NEXT_PUBLIC_COGNITO_DOMAIN`).
- `AuthGate` redirects unauthenticated users to `/auth/login`.
- Callback route handles OAuth code exchange.
- Session tokens stored server-side (HttpOnly cookies via BFF proxy) — never in `localStorage`.
- Token refresh: silent refresh in the BFF proxy on 401 from backend.

4. BFF Proxy
------------
- `app/api/proxy/[...path]/route.ts` runs on the Node.js runtime.
- Reads session token from server-side cookie.
- Forwards to `BACKEND_ORIGIN + /` with `Authorization: Bearer <token>` and `X-Correlation-Id`.
- Streams responses for content-type `text/event-stream` and JSON responses passthrough.
- CSRF: same-origin only; POST/PUT/DELETE require a matching `x-csrf-token` cookie set at login.

5. Design System
----------------
- Tailwind for layout + spacing.
- `shadcn/ui` components initialized: Button, Input, Sheet, Toast, Table, Badge, Card, Tabs, Dialog, Skeleton.
- Theme: light + dark; persisted preference.
- No third-party icon set beyond `lucide-react` (already used by shadcn).

6. Local Dev
------------
- `pnpm dev` runs with MSW enabled by default (mocks all `/proxy/*` calls) unless `NEXT_PUBLIC_USE_LIVE_BACKEND=true`.
- MSW handlers cover: `/health`, `/findings`, `/decisions/{id}`, `/agent/chat` (non-streaming), `/operations/health`.

7. CI
-----
- `pnpm typecheck`, `pnpm lint`, `pnpm test`, `pnpm build` on every PR.
- `openapi-typescript` regeneration checked in; PR fails on drift.
- Playwright smoke run on PR (headed=false).

8. Acceptance Criteria
----------------------
- [ ] `pnpm dev` boots with MSW; landing page renders with auth gate.
- [ ] `pnpm build` produces a static output tree suitable for Amplify Hosting or CloudFront + S3.
- [ ] Auth flow (login → callback → dashboard) works in Playwright.
- [ ] axe-core scan clean on layout and login pages.

9. Risks & Mitigations
-----------------------
Risk: Cognito hosted UI CORS misconfig.
  Mitigation: config validated at build; smoke test in staging catches CORS issues.

Risk: token exposure in browser bundle.
  Mitigation: BFF proxy pattern; tokens never in JS bundle.

Risk: MSW hides real API bugs.
  Mitigation: `pnpm test:e2e:live` variant runs against dev backend nightly.
