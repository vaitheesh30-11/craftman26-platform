## 2. Directory Layout & Module Responsibilities

Codex must generate the Phase F1 architecture within this strict structure:

* **`frontend/`**
  * **`src/`**
    * **`app/`** — Next.js 14 App Router directory.
      * **`layout.tsx`** — Root layout incorporating global providers (QueryClient, ThemeProvider).
      * **`page.tsx`** — Global dashboard view (List of drift sessions).
      * **`sessions/[id]/page.tsx`** — Deep-dive HITL workspace for a specific session.
    * **`components/`**
      * **`providers/`** — Wrappers for React Query and Auth Context.
      * **`ui/`** — Reusable, atomic design components (Tailwind + Radix/Shadcn).
      * **`layout/`** — Sidebar, Navigation, and Header components.
    * **`store/`**
      * **`useSessionStore.ts`** — Zustand global store for volatile UI states (sidebar toggles, active tabs).
    * **`lib/`**
      * **`api-client.ts`** — Axios instance configured with base URLs and interceptors.
      * **`auth.ts`** — Server-side token validation helpers.
    * **`types/`**
      * **`dto.ts`** — Strict TypeScript interfaces matching the backend Pydantic V2 schemas.
  * **`middleware.ts`** — Next.js Edge middleware for route protection.

---

## 3. Technology Stack & Runtime Constraints

The implementation must strictly adhere to the following framework choices:

* **Framework:** Next.js 14 (App Router exclusively, no `pages/` directory).
* **Language:** TypeScript (Strict mode enabled, no `any` types).
* **Styling:** Tailwind CSS integrated with `clsx` and `tailwind-merge` for dynamic classes.
* **REST Data Fetching:** TanStack React Query v5.
* **Volatile UI State:** Zustand.
* **Component Library Target:** Shadcn UI / Radix Primitives (accessible, unstyled core components).

## 5. Security Guardrails & Auth Architecture

### 5.1 Next.js Edge Middleware (`middleware.ts`)
* **Execution:** Runs on the Edge runtime before every request.
* **Logic:**
  1. Intercepts navigation to `/sessions/*` or `/dashboard`.
  2. Reads the `sentinel_auth_token` from secure HTTP-Only cookies.
  3. If missing or malformed, redirects the user to `/login`.
  4. If valid, allows the request to proceed.

### 5.2 API Interceptors (`lib/api-client.ts`)
* Uses Axios.
* Injects the `withCredentials: true` flag to ensure cookies are sent to the FastAPI backend.
* Implements a global error interceptor: if the backend returns HTTP 401 (Unauthorized) or 403 (Forbidden), it triggers a client-side route push to the login page and wipes local state.

---

## 6. Global State Architecture

### 6.1 React Query Configuration (`components/providers/QueryProvider.tsx`)
* Sets global `staleTime` to 60 seconds to prevent aggressive re-fetching.
* Configures `refetchOnWindowFocus: true` so the dashboard automatically updates if a security admin switches tabs and returns.
* Implements `keepPreviousData` for smooth pagination transitions on the session list view.

### 6.2 Zustand UI Store (`store/useSessionStore.ts`)
* Manages purely client-side, ephemeral state that does not need database persistence.
* **State Values:**
  * `isSidebarOpen`: boolean
  * `activeWorkspaceTab`: 'DIFF_VIEWER' | 'TOPOLOGY_MAP' | 'DEBATE_LOG'
  * `setWorkspaceTab(tab)`: function

## 7. Execution Directives for Codex

When assigning Phase F1 to Codex, instruct it to:

1. **Initialize App Router & Types:**
   * Create the strict TypeScript interfaces in `src/types/dto.ts` matching the backend schema exactly.
   * Generate `src/app/layout.tsx` defining the global HTML shell, font loading (e.g., Inter), and CSS imports.
2. **Implement Security Middlewares:**
   * Generate `middleware.ts` at the project root to enforce cookie-based route protection.
   * Generate `src/lib/api-client.ts` setting up the Axios instance with credential inclusion and 401 interceptors.
3. **Configure Global State Providers:**
   * Build `src/components/providers/QueryProvider.tsx` wrapping the application in TanStack Query.
   * Build `src/store/useSessionStore.ts` using Zustand for the UI toggle states.
4. **Scaffold the Primary Views:**
   * Create `src/app/page.tsx` as the paginated data-table layout for viewing `SessionSummary` lists.
   * Create the skeleton for `src/app/sessions/[id]/page.tsx` which will house the HITL workspace.
